# シャテッキ｜r007 後続対応の敵対的レビュー記録

2026年11月20日。[後続対応の計画](../superpowers/plans/2026-11-20-r007-followup.md)を、わざと意地悪な目で読み直した記録です。「この計画どおりに進めると、どこで見落としや思い違いが起きるか」を問い、見つけたものごとに計画か実装を直しました。

ここでいう敵対的レビューとは、計画や試験が「通ったように見えて、実は確かめていない」場所を探す読み方のことです。以下ではただ「見直し」と呼びます。

## 見直しで見つかったこと

### 1. 試験の押す時間が、プレイヤーの押し方と違っていた

最初のブラウザ試験は、「撃つ」を押してから 0.58 秒待って「発射」を押していました。node 側の試験は 36 コマ（0.6 秒）待ち、強さは「ぴったり」でした。ところがブラウザでは、押すまでの遅れが毎回少しずつ違い、強さが「弱い」になって景品が落ちませんでした。

ここで期待値をゆるめる（落ちなくても合格にする）ことはしていません。代わりに、6つの開始状態それぞれを node で 0〜60 コマの間で撃ち分け、「弱い」以外ならどの強さでも同じ結果になることを確かめました。そのうえで、ブラウザ試験はプレイヤーと同じく、ゲージの帯を見てから押す形に変えています。押したあとの強さが「弱い」でないことも、保存された記録から確かめています。

### 2. 強さの表示が、実際の強さより弱く出ていた（不具合）

上の調べものの途中で、ゲージの下の文字が、帯が「つよい」や「ぴったり」に入っていても「ふつう」と出ていると分かりました。帯は内側ほど狭く入れ子になっているのに、いちばん広い帯から探していたためです。プレイヤーは実際より弱いと思って押すことになります。

これは試験を先に書いて直しました。0 から 1 までの 1001 個の値と、帯の幅 0.85・1・1.25 倍のすべてで、表示の強さと発射の強さが一致することを確かめる単体試験です。直す前のコードではこの試験が失敗し（0.723・0.85 倍で「ふつう」と「つよい」が食い違う）、直したあとは通ります。

### 3. 「重ならない」を、目で見るだけで済ませそうだった

計画の T05 は「3寸法で重ならない」でしたが、画面写真を目で見るだけでは、細い重なりを見落とします。そこで、札・弾・点・操作欄・吹き出しの枠の位置を測り、重なれば失敗する試験にしました。

その結果、うちわの場面（402×874）で、札が右上の点と全体図に重なっていることが見つかりました。札の上端が固定の値で、上の列（次の射の予約・遊び方の札・全体図）が増えると届かなかったためです。札を出すたびに、上の表示の下端と操作欄の上端を測り、その間に置くよう直しました。

### 4. 負荷の数値を、端末の結果と取り違えそうだった

試験機の Chromium は画面のない状態で動き、絵をソフトウェアで描きます。ここで測ったコマ間隔（狙っている間の中央値 33 ミリ秒、飛んでいる間 50 ミリ秒）は、iPhone の結果ではありません。計画にある「60コマを目標、30コマを下限」は、この環境では判定できません。記録には数値と一緒にその旨を書き、合否は付けていません。

### 5. 当たり判定を変えると、前に確かめた反射の結果が変わるおそれ

うちわを四角から円に変え、前腕に当たる箱を足しました。これで、前に確かめたうちわ・盆の反射取りや、帽子・足元・胴の結果が変わるかもしれません。店主の統合試験（17件）と、場面の開始状態の試験（8件）をやり直し、すべて通ることを確かめました。四角の角（円の外側）がうちわにならないこと、円の内側はうちわになること、前腕は「体」になることも、新しい試験で確かめています。

### 6. CI が r007 の試験を選ばない変更があった

GitHub Actions は、変わったファイルに合わせて試験を絞り込みます。その規則を読むと、画面部品（`src/ui/`）や文言（`src/i18n/`）だけを変えたとき、r007 の単体試験と画面試験が選ばれませんでした。r007 の画面だけを壊す変更が、試験を通ってしまうおそれがあります。規則に r007 の試験を足し、規則そのものの試験（158件）も更新しました。必須の試験を減らす変更はしていません。

### 7. 自動プレイヤーの比較を、人の遊び方と取り違えそうだった

T09 の比較は、決まった規則で狙う自動プレイヤーの結果です。人の考える時間は入っていません。飛行秒数も、メニューや考える時間を含みません。r007 で右の壁のマスに当たる回数が左の倍以上なのは、店主（右端）を狙う動きを自動プレイヤーに入れているためかもしれません。これが人の遊び方でも起きるかは、分かりません。値を変える提案は、この点を明記してから出します。

### 8. 札の景品の絵が空白だった（公開版にも及ぶ既存の不具合）

3寸法の画面写真を見直したところ、セット札の「桜の飾り」の絵が空白でした。調べると、景品の絵をまとめた画像（`src/view/assets/prize-atlas.webp`）で、100種のうち14種（P003・P014・P016・P018・P019・P024・P028・P043・P053・P075・P080・P092・P095・P099）が空白でした。

原因は、景品の形を当たり判定の円柱に収める処理です。上の端の頂点が、32ビットの小数の丸め誤差で円柱の上面をごくわずかに超えると、「どこまで縮めても収まらない」と判断して、横幅を0まで縮めていました。そのため、これらの14種は棚の上でも見えない線になっていたはずです。公開中の9枠版にも同じ処理が使われています。

試験を先に書き（14種すべてで幅が0になることを確かめて失敗）、判定に 1e-7 m の許容を入れて直しました。絵の画像も、既存のスクリプト（`scripts/art/render-prize-atlas.mjs`）で作り直し、空白の枠が0になったことを確かめています。当たり判定・点・保存は変わりません。ただし、**公開版9枠の見た目も変わります**（14種が棚に見えるようになります）。マージするかどうかは利用者の判断です。
