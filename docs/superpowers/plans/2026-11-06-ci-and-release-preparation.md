# 変更範囲に合わせる自動確認と公開準備

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全試験の反復とビルドの重複を減らし、確認を省略した理由を記録する。残る公開作業を実行可能な設定案にする。

**Architecture:** 変更一覧から文書のみ・対象試験・全試験を選ぶ。未知の変更や共通処理は全試験へ戻す。Node試験とビルドを並行し、ビルド成果物を2分割したブラウザ試験へ渡す。必須の確認名testは最後に集約する。

**Tech Stack:** GitHub Actions、Node組込み試験、既存Vitest／Playwright。

**Spec:** 利用者の2026-11-06「毎回全部のテストは不要」「並行するなど時間短縮」と、docs/requirements.md・既存CIの0件/skip検査。

## 制約と選択

- 依存関係・共有型・物理・採点・保存・起点・CI自体の変更は全試験。文書だけならゲーム試験を起動しない。
- 機能ごとの明示的な対応表を採用。自動の依存解析だけへ任せる案は、動的読込やファイル読み込みを取りこぼすため採用しない。未知のファイルは全試験。
- 全試験は手動でも指定可能にする。今回だけはCIそのものを変えるため新構成で全試験を一度確認する。
- main直push・自動マージ・本番DB変更・ゲームルールの正式採用はしない。公開設定はまだ実行されないテンプレートで具体化する。
- 新規従量課金を有効化しない。並列化は既存の公開リポジトリのCI内で行う。

## Review Focus

- 文書とコードの混在、削除、改名、比較元不明で試験が抜けないこと。
- 必須のジョブが失敗・中止・想定外のskipになったら最後のtestも失敗すること。
- ブラウザ試験が別コミットの成果物を使わず、同じ成果物で全56件を分担すること。
- 文書変更だけで必須チェックがPendingのまま残らないこと。
- 公開テンプレートを追加しただけで外部公開しないこと。

## Task 1: 変更判定と実行

担当Aはscripts/ci/とtests/ci/のみ。失敗試験→分類・実行関数→成功試験。planChanges(paths,{forceFull})からscope、各試験一覧またはall、node/build/browserの真偽を出す。ゼロ件の選択と試験0件合格を区別する。

## Task 2: 並行実行・成果物共有・集約

主担当は.github/workflows/ci.ymlとplaywright.config.ts。Node試験と型検査/ビルドを並行。ブラウザ2分割は同じrunのsite-distを使用。testを必須の集約名として維持し、必要な結果だけを厳密に照合する。古いrunはキャンセル。

## Task 3: 公開準備と申し送り

担当Bはdocs/release/preview-pages.yml.exampleとpreview-ready.mdのみ。成功したmainのCI成果物を使うPages設定案を作り、再ビルド・全試験の重複を避ける。公開・正式値・DBの未決定事項を勝手に承認しない。

## Task 4: レビューと提出

- [x] 分類試験と実際の対象試験を確認する。
- [x] 独立レビューで取りこぼし・skip誤判定・成果物の混在を確認する。
- [ ] 新構成の全試験を一度だけGitHubで実行し、以前の約4分12秒と所要時間・実行範囲を比較する。
- [ ] 専用ブランチからmain宛のPRを提出し、CI成功まで対応する。

## レビューで修正した点

景品候補のMarkdownは実際に試験から読まれるため、対応するセット候補表とともに全試験へ戻す。音・翻訳でも安全性試験を残し、翻訳では操作状態の案内文の確認も選ぶ。Playwrightの分割時には0件が成功になるため、新しく生成した結果ファイルの成功件数が正で、省略・失敗・flakyが0であることを追加で検査する。いずれも失敗する試験を確認してから修正した。

手元ではCI用149件、言語31件、結果表示44件が成功。新構成の全体確認と実測時間は提出PRのCIへ記録する。公開用設定は実行されないテンプレートとして保存する。
