# 正式初期値・ランキング非公開での公開

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 利用者が今回許可した正式値採用・本体公開・DB適用を、ランキング非公開・実験場未連携の条件で実行する。

**Spec:** 2026-11-06利用者「正式値の採用と本番公開(ランキングは非公開、実験場への連携はまだしない)、データベース適用まで対応」。確定01〜33は維持する。

## 採用する範囲

現行の100景品・100セットと採点・物理・抽選・装填などの数値を変更せず、初回正式版rules-v1として採用する。未選択のセット補助案Cは追加しない。名称はプロジェクト名「シャテッキ／Shatekki」を使う。

DBには正式設定の版保存をprivate.shatekki_releasesへ適用する。参加者・スコア・公開RPC・public.gamesの登録は作らず、実験場とは接続しない。本人順位v2の共通基盤変更は今回実行しない。

## 作業

1. 正式設定を試作の試験データとは別に作り、数値不変と全承認済みを確認する。
2. ホームの名前入力・ランキング、結果の送信/順位/一覧を隠す。開始・終了・再送・一覧取得の通信も止める。既存の保存名・自己ベスト・図鑑・送信待ちを消さない。
3. 最終ソースからJSONを書き出し、非公開テーブルにRLSと権限制限を適用。同じ版の別内容を上書きしない。100件ずつの内容・参照・ハッシュ・匿名アクセス拒否を確認する。
4. GitHub Pagesの配信設定を有効なワークフローへ移し、成功した同一CI成果物を使う。mainへの変更はPRとして提出し、マージは従来どおり利用者が行う。
5. 公開設定への認証が必要な場合は通常のログインを使い、認証先の自動承認審査で拒否された操作を回避しない。公開完了はURL到達と公開画面で確認して初めて記録する。

## 検証

手元は正式値・非公開画面・共有文と言語の対象試験を確認する。app/catalogという共有範囲を変えるため、CIで全試験を一度確認する。iPhone Safari実機は別の未確認項目として残す。
