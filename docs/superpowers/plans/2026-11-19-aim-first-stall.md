## 着手順と提出単位

| 工程 | 前提 | 実際に触って確認する終点 |
|---|---|---|
| 1 操作・保存 | 基準版の回帰を固定 | 開始から照準、左右へ移動、初射・次射、再読込後の継続。 |
| 2 背景と命中 | 候補の設定・配置の共有型を工程1で確定 | 100マス、境界、遮蔽物、粒、同じ射で複数効果。 |
| 3 射の意味・セット札 | 1と2の結果の型を確定 | 空振り、使用済み、補給上限、組の同時成立を実射から結果まで確認。 |
| 4 店主と台詞 | 操作欄と優先表示位置を確定 | 人型モデルと命中位置。状況別の吹き出し。質問と同時に出ない。 |
| 5 統合・比較 | 1〜4を統合 | 15言語の表示、3寸法、実機で見る箇所、公開判断用の証拠。 |

第1・2工程と、第3・4工程は、それぞれの境界が決まり次第、担当パスを分けて並行できる。ChatGPTが操作・ゲーム処理・美術・音・翻訳・試験を担当する。共有型、`src/app.ts`、結果の確定、確認設定への変更は順番に取り込む。各実装PRでは関連する試験を先に追加し、意図した失敗を確認してから当該工程を実装する。

## 工程1　照準から始め、威力を決めた一操作で発射する

主に `src/app.ts`、`src/app/{bundle,controller,rules}.ts`、`src/core/{state,transitions,aim,loading,rewards,session}.ts`、`src/contracts/{game,expansion,persistence}.ts`、`src/ui/controls/`、`src/persistence/indexed-run-repository.ts`、`src/catalog/gameplay-config.ts` と `data/expansion-v2/next-profile.json`。

- [ ] 内部候補に `expanded-aim-first` と新キー `rules-v2-proposed-r007` を割り当て、設定を起動時に選ぶ。正式9枠とr001〜r006の実行設定・保存先を分ける。新候補の進行中データを古い版に読み込ませず、旧ベスト・図鑑・名前・設定・送信待ちの既存データを保持する。日替わりはr007の日付と版を種にする。
- [ ] r007の開始と確定後の生存状態を位置確定不要の `aiming` にする。この状態は `load=null` を許す。左右のボタンは短押しで0.14 m。押下を捕捉し、長押し時は固定刻みで移動し、左右端で止める。短押し分は短押しとして離した場合のみ加算する。端での長押しや多指操作の終了、操作フォーカス消失、`pointercancel`、非表示で必ず解除する。短押し、長押し、照準ドラッグは操作完了時に `runId/aim/連番` で最後の位置・照準を一括保存する。長押し中の各描画では保存しない。中断した入力と保存失敗では安定状態を再表示し、再試行時に同じ操作を使う。保存待ちは重ねて撃てないようにする。照準は本人が決めた角度を使い、照準・弾の方向・予測線・装置の接触の全入口で同じ値を使う。鼓動の音・手ブレを説明する文・ランタイムの揺れ倍率は候補の経路から外す。
- [ ] 「撃つ」を受理すると保存する安定状態からゲージを開き、スナップショットに位置と照準を確保する。1回目の操作の `pointerup` やキー自動繰り返しが2回目にならないようにする。取消では弾と次射の予約を保ち、固定していた位置と照準へ戻す。2回目は表示結果を入力値として受け取らず、固定刻みの時計から `classifyLoad` を呼び、`LoadResult` と発射要求を同じ更新で作る。r007の発射直前の遷移の起点は `loading`。既存 `GameController.finishCommand` の `aiming → resolving` に固定した条件、開始・精算後の `position` 固定、発射保存の妥当性検査、`validateRunState` の照準時の `load` 必須条件、空間予測用の `FIRE` 試行を合わせて見直す。予測用は要求作成を副作用のない処理へ分け、毎描画で同じ照準の予測を計算し直さない。FX098の線と補給装置の照準は威力決定前も出せるようにする。コルクの半径を使う実際の最初の接触を、背景と店主に対しても表示と共有する。照準前に威力が未確定でも使える基準値を、弾道に必要な項目だけに与える。A5は照準中に左右へ追従する予告、ゲージを開くと固定、発射を保存した時だけ試行済み。取消で予告へ戻す。
- [ ] `runId/shotNumber/fire` を既存の一括確定で使う。書込み中は入力を止め、書込み前の失敗でコルク・音・弾数が進まないことを確認する。同じ操作の再試行では最初に押したゲーム内刻み、威力、位置、照準を再利用。保存済み応答消失・別タブの競合・背景化の直後に、保存成功を二回目と誤認して実射を繰り返さない。最終確定にも同じ射の番号を使う。安定状態を開き直したらゲージは閉じ、発射済みの未確定は既存方針で中断する。旧版向けの既存入力型と保存は引き続き試験する。
- [ ] 新モードの `powerZoneWidthMult` を型、範囲検査、保存、抽選、結果、15言語に通す。既存FX012/013/035/036のr007用操作を別データで定義する。基準の距離0.05／0.15／0.35に倍率を掛けて各区画の端を0〜1に収め、境界上は強い側を先に判定する。各段階が同じ中心の入れ子になることを検査。FX037/038の時間係数と併用、FX082のリセット、同一範囲効果の後勝ち、質問経由と背景の同時予約を確認。次射予約が0弾の途中経過で消えないことも試す。

**確認**　`tests/unit/expanded-transitions.test.ts`、`tests/unit/gameplay-effects.test.ts`、`tests/integration/daily-determinism.test.ts`、`tests/e2e/persisted-gameplay.spec.ts`。候補用の画面試験 `tests/e2e/aim-first.spec.ts` を加え、移動1押し・長押し→照準→2タップ→残弾9→同じ照準へ戻る経路を3寸法で通す。旧9枠・r006は従来どおりの遷移と復帰を同じ差分で確認。

## 工程2　マスを増やし、接触した実位置に反応を出す

主に `src/contracts/{layout,layout-v2,ids,events}.ts`、新規 `src/contracts/layout-v3.ts`、`src/sim/world.ts`、`src/core/{background-cells,effect-plan,expanded-run}.ts`、`src/view/{background-cells,effects,expanded-view,renderer}.ts`、`src/ui/booth-map.ts`。

- [ ] 100マスの配置を[面の寸法](../../design/2026-11-19-aim-first-stall-art.md)から生成。背面の既存36マスと景品枠の対応を保ち、追加の背面34・側面30には面・行・列が区別できる安定IDを割り当てる。追加64マスに架空の景品枠を作らない。割当・使用済み・保存の検査ではID集合を配置から渡す。旧版の固定36件と新候補の100件を別の検査設定で扱う。
- [ ] 背面と側面の各面に、見た目と当たりを共用する接触面を一枚ずつ置く。景品の剛体接触は通常の反射面として残す。コルクの最初の接触位置から面上の座標を取る。背面はx/y、左右はz/yとし、面の名前を座標とともに渡す。区画の区間は小さい座標を含み大きい座標を除く。最外周の端だけ含める。面の角に同時到達したら背面→左→右の順に1面へ割り当て、同じ接触の再通知で別マスを消費しない。物理時刻の異なる反射と別のコルクの接触はそれぞれ判定。演算誤差を吸収する境界許容値は一箇所に置く。装置と景品が先に当たる位置は既存の最初の接触の規則を優先する。風鈴を用意する反射面の対象は、壁・背景マス・棚板に限る。
- [ ] 上・下・両端・側面を全体図に反映。背面は段列、側面は分かれた小枠で表示する。現在見える範囲と「？／✓」を追う。発動時の札と残弾の脇には、予約された効果の共通印を出す。上書き・取消・再読込時に古い印が戻らないことを確かめる。姿を隠す柱やカウンターの裏に当たる表示を置かず、背面の上下・左右端、左右の各壁の手前／中央／奥で、画面上で狙える実射を記録する。現行の立ち位置±2.35・銃口z=-0.30・左右角±0.3で側面の前2列に直接届かないことを再現し、描写文書の候補の寸法から始める。左右から同じ条件で確認し、各段も直射または反射で少なくとも1射を記録する。全100マスの幾何学上の被覆を検査し、普通の構えと反射でも継続的に狙えない区画は記録し、仕切りや装置の遮蔽を調整してから受入判定する。
- [ ] 接触の `eventId`・座標・法線・素材を、現行の描画キューへ渡す。固定刻み複数回分を蓄積し、1回描く前の接触を落とさない。止まるまで同じ接触を繰り返し飾らない。高負荷では接触点ごとの小さい印を先に出し、補助の粒を減らす。画面外は方向の印、音量ゼロは視覚で分かる。被弾の粒、マスの発動印、得点の演出を別の出来事として扱う。

**確認**　`tests/unit/background-cells.test.ts`、`tests/integration/next-background-contacts.test.ts`、`tests/integration/next-composite.test.ts`、`tests/integration/next-device-view.test.ts` を拡張。100マスを同じ画面間隔2条件で試し、角、境界の両側、使用済み、複数マス、背景の前にいる景品・店主と補給装置を照合。幾何学検査と通常操作で当てる検査を分ける。現行ボードの3段×12列は実寸を比較する。

## 工程3　すべての確定射に理由を残し、セットで大札を出す

主に `src/contracts/events.ts`、`src/sim/world.ts`、`src/core/{expanded-settlement,result}.ts`、`src/app.ts`、`src/ui/{effect-results,reward-panel,result}.ts`、`src/view/{classify,reward-motions,effects}.ts`、`src/audio/`。

- [ ] 景品/セット/補給/効果、代表接触、弾の終了理由と境界側を、順序のある事実として確定要約に入れる。代表接触は、獲得などの確定情報が弱い場合に、景品→マス→装置その他の順、同順位なら接触順で実イベントから一つ選び、画像から逆算しない。台詞のキー選択は優先順で決める。処理中はまだ判定を出さず、分裂弾の遅い命中、質問、落下の猶予を待つ。以前の「ハズレ」の文と外れ専用音をr007では使わず、上限、使用済み、点数0、無接触を説明できる形にする。
- [ ] 空振りの終端は、出口が分かるなら方向別。上下左右・奥・手前は実軌道と境界の交点に基づく。同じ時刻に2境界へ達する角では横→縦→奥行きで一つを選び、飛行上限や速度で止まったときは時間・失速として分ける。分裂弾の複数終端は、最初に受理した一射の元弾とその子の安定した順で代表を選ぶ。終端が特定できない場合にも次の狙い直しの文を一つ用意。獲得・加点・装置の成功は実績があるときだけ表示する。弾や点数を増やすためだけに使用済み装置・空振りを狙う利点を加えない。
- [ ] 成立札には `ledger.items` のセット項目ごとの点・合計と、その射の `scoreAfter` を渡す。既出の組でもその回の新しい成立なら表示。実際の初発見は開始前の図鑑との差に基づく。複数組は一枚で名前別の点を読める。初発見の印とセット加点は別の値。補給は旧装置・背景・回答・A1〜A10全元の実増加と残弾を短い欄に出す。上限で実増加0・減弾がある場合も、表示の合計や純増と混ぜない。最後は結果の欄で全件を読める。短い効果欄の件数制限に埋めない。
- [ ] 一射1回の大きな表示と音。順序はセット成立→最終弾から続行→まとめ取り→短文。途中のアニメーションを閉じても次の操作に影響しない。ユーザーがすぐ進んだ場合も、結果に残った最後の射で詳細を読める。前回の射の遅れた表示を次の射に流さず、決済の再読込では保存済みの内容だけを静かに出す。

**確認**　`tests/unit/reward-panel.test.ts`、`tests/unit/result-expanded.test.ts`、`tests/e2e/confirmed-set-cards.spec.ts`、`tests/integration/next-composite.test.ts` を拡張。最低でも無接触・景品を押すだけ・使用済み・補給上限、同時ペアと3景品、最後の1発で複数効果と補給、生存/終了、演出省略・音量0・再読込を一つずつ確認。表示処理の後も得点・残弾・図鑑の保存が同一かを比べる。

## 工程4　より人らしい店主と、台詞100種を入れる

主に `src/view/{shopkeeper,booth,effects}.ts`、`src/app.ts`、候補の新規 `src/ui/shopkeeper-speech.ts` と `src/i18n/stall-speech/`。

- [ ] [描写仕様](../../design/2026-11-19-aim-first-stall-art.md)に従い、右端の店主を立体として作り直す。頭や手を絵と当たりでずらさない。うちわ・頭部の飾り・胴・足の候補形状と動く範囲を配置と共有し、店主の手前の装置と背後のマスをそれぞれ直接撃って初接触を確認。帽子に相当する部位等は既存の初回点と質問の一射1問にひも付ける。表情と手振りは衝突の動作と切り分ける。
- [ ] 台詞表を安定IDの辞書へ移し、分類と発話条件を本文から分ける。話せる時間で6秒・以後12秒。専用の乱数系列で、直近5件を除いて条件が通る原稿から1件だけ選び、4.5秒を目安に表示。タイマーは画面側に置き、ゲームの固定刻み・ランダム効果・得点の処理に入力しない。文面の未選択とロード失敗では発射を止めない。質問/注文と別の表示にし、停止・非表示・ゲージでは遅延発話を繰り越さない。表示位置が話者と照準を遮るときは上側へ移す。
- [ ] 日本語100種を読み合わせ、確定画面が揃った段階で既存15言語の各本文を整備する。台詞、注文、質問の識別子が混ざらないよう検査し、有効にしたギミックに合うヒントだけを出す。通常・日替わり、店主が画面外、短い縦、質問割り込み、復帰、長文、動きを減らす設定を画面で確認する。

**確認**　新規 `tests/unit/shopkeeper-speech.test.ts` と `tests/e2e/stall-speech.spec.ts`。最初の6秒、12秒ごと、一時停止中の経過でまとめて出ない、質問に同じ1回だけ答える、異なる表示言語の台詞を出しても同じ軌道と得点になることを確認する。

## 工程5　統合して、同じ版で結果を残す

- [ ] 候補の各工程を通常・日替わりに接続。途中の書き戻しと旧版読込を先に確認。新ゲーム開始→照準→移動→発射→質問/セット→最後の射→結果→もう一回。最新候補の同一コミットで関係する型・単体・統合・画面試験、旧9枠・r006を含む回帰を行う。文書だけの検証をゲーム試験の成功に数えない。
- [ ] 3寸法の画面比較に、左右端、移動・照準、威力ゲージ、質問、全体図、店主、粒、セット成立、無接触の行、結果を残す。任意の条件を模した試験と実際に撃って再現した記録を区別する。iPhone 17 Pro Safariでは短い縦、横から復帰、縦で連続3回、音、熱、100マス描画と粒の負荷を計測。既存基準の目標60コマ毎秒／下限30の測定を飛行・確定直後に分ける。
- [ ] 9枠・r006・新候補を既存と共通の24種で比較する。照準と威力の入力時刻を別々に保存し、照準・得点・弾の差を再現できるようにする。各面の命中率、無接触と短文の比率、2組以上の発生、補給とプレイ時間、セットの読みやすさを記録する。内部候補の正式値・実機記録・公開用既定の切替は[既存の採用手順](../../release/expanded-adoption.md)に従う。マージは利用者。ランキング・実験場への連携は別に扱う。
