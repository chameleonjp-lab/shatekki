**版**：1.1、2026-11-06。検証元：PR #5マージ後の `0c101688dcd07af0a5e01c8f62f4daebe89fb7bd`。旧計画の本文を置き換える。

## 正本・対象・追加しないこと

[要件](../../requirements.md)、[決定01〜33](../../decision-log.md)、[AC01〜AC45](../../acceptance-criteria.md)、[残る13分類](../../open-items.md)、[景品](../../prize-candidates.md)・[セット](../../set-candidates.md)・[候補JSON](../../../data/catalog-candidates.json)を読む。[対応表](../../reviews/shatekki-plan-traceability.md)に担当と試験を記載する。

利用者の最新の明示的な決定が最優先。次にmainの決定記録・要件書、本計画。要件書の仕掛け表に旧「未確定」が残る場合も、決定28・31・32を再び未決定にしない。未マージの提案は決定ではなく、未定値の承認はChatGPT単独では行わない。ChatGPTは根拠を整理し、ルール・得点・体験を変える判断は利用者へ示す。

景品100種類、セット100種類、初期10発、追加累計10発まで、初期9個（3段×3）、縦向き、軽量3Dを維持する。補充延期中に9個未満になることは決定30によるもので、未獲得個体を削除して9個へ戻さない。最大20回は発射回数であり分裂弾数ではない。

初期の上限案はOpus 1＋Sonnet 2。同時にGameとVisual、またはGameとUIを選び、もう一方は交代で担当する。人数の追加は利用枠と承認を確認する。既に与えられた対象・費用範囲の許可を毎タスクで取り直さず、範囲が変わる時だけ確認する。

Agent Teamsは環境で対応を確認してから利用する。使えなければ同じ役割でサブエージェントまたは順次実行する。公式資料には `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` が案内されているが、この資料更新では設定を有効化しない。ワーカーの実モデルを起動時に確認し、リーダーのモデル変更だけで全員が切り替わったと考えない。Teamsの連絡・タスクリストと、編集作業場所の分離は別である。

## 並行編集と申し送り

並行して書き込む担当は別ブランチ・別作業場所を使用する。各作業場所について `git status`、ブランチ、開始SHA、担当パスを記録する。分離が使えなければ書き込みを直列化する。共有型、package/lockfile、起動・CI、配線の統合はOpusだけが編集する。複数ワーカーの成果はmainではない統合ブランチで再試験し、採用したコミットを記録してPRにする。main直push、自動マージ、承認のないforce push・削除は禁止。

タスク状態は `READY → WORKING → REVIEW → PR_OPEN → MERGED` とし、阻害時は `BLOCKED`。Opusだけが台帳を更新し、担当、基準SHA、変更パス、依存、試験、PR、未確認事項を記録する。エージェントの「完了」は証拠を伴うREVIEWまでで、依存タスクをMERGEDとみなさない。未マージの先行変更を使う場合は明示した積み重ねPRに限定し、採用基準SHAと親PRを記録する。

[申し送り規約](../../handoff/protocol.md)に従う。相手用の別リポジトリは未指定なので、現時点の窓口は同repoの `docs/handoff/to-claude/` と `to-chatgpt/`。別repoの指定後は宛先・権限を確認して送信し、同一案件IDと参照リンクを保持する。メモを残すだけで相手のAIが自動起動・受領したとは考えない。未マージPRも参照・回答は可能だが、未承認の仕様を実装へ取り込まない。返答待ちの箇所だけ止め、独立作業を進める。

|---|---|

| `RunState` | runId、rulesVersion、phase、pause理由集合、所持弾、追加累計、発射回数、得点、獲得個体、獲得種類、成立セット、装置・部位の使用済み情報 |

| `ImpactEvent` | eventId、runId、shotId、projectileId、対象ID、接触座標・法線・材質。画面外でも生成し、得点通知とは分離 |
| `SimulationFrame` | 読み取り専用の物体姿勢と接触イベント。Visualは一射の確定を待たず動きを描けるが、物理状態を書き換えない |
| `ShotSummary` | shotId、獲得instanceId/typeIdの対応、成立setId、追加弾、連鎖個体数、得点台帳。eventIdとinstanceIdの二段階で重複防止 |
| 得点台帳 | scoreBefore、景品/技/セット加点、名目減点、適用減点、scoreAfter。表示・保存・共有・送信が同じ確定値を使う |
| `Checkpoint` | schemaVersion、runId/rulesVersion、確定射ID、抽選状態、棚・運動位相、延期枠、装填結果、開始時の名前、状態と送信済み識別 |

予定関数は `createRun(config,name): RunState`、`reduceGame(state,command): RunState`、`advanceSimulation(state,dt): SimulationStep`、`resolveShot(state,events): ShotResolution`、`drawPrize(catalog,drawState,config): DrawResult`、`validateCatalog(data): CatalogValidationResult`。入力・戻り型をTask 02で定義し、各担当が独自名を増やさない。外部データだけはunknownから検査して型を絞る。物理の固定時間刻みやseedは再現試験用で、別端末間の完全同値を保証するものではない。

## 先に守る処理順と失敗条件

一射は「発射受付・弾消費 → 飛行/接触 → 飛行終了 → 予約変身 → 変身後を含む落下判定 → 取得・セット・加減点・追加弾を一度確定 → 残弾確認 → 続行時だけ補充 → 次射用保存」とする。保存の実装は結果台帳と補充後の状態を同じ版へまとめ、読み直しで補充を二重抽選しない。反射上限後の有限猶予を繰り返しリセットして無限化しない。具体時間、変身対象、端数、猶予後の扱いはO07/O08として決定してから本番利用する。

一時停止はphaseを失わない独立した状態。非表示・横向き・手動停止の全理由が解消し、再開操作があるまで、装填・鼓動・物理・周期景品・音を止める。停止解除時に経過時間をまとめて物理計算しない。ページが保持された停止と、ページが失われた再読み込みを区別する。

発射済み・未確定の印と最後の確定状態を区別し、印が残った復帰は決定27の中断で完了送信しない。書込み途中、保存失敗、複数タブ、終了確定後の再送も検査する。保存失敗時のプレイ継続表示など未定の体験はO11で決め、壊れた状態を正常復帰として採用しない。

重点反例は、最後の弾→分裂→追加弾→複数セット（08/09/10）、下段移動で補充が塞がる（06）、高速/画面外反射（05/08）、再読み込みと送信再試行（10/16）、音・長文翻訳・短い縦画面（13/14/15）。

## 試験・証拠の共通手順

Task 01で `npm ci`、`npm run typecheck`、`npm run build`、`npm run test:unit -- <path>`、`npm run test:integration -- <path>`、`npm run test:e2e -- <path>` を実行できるようにする。選定ツールに応じたscriptとテストファイルを用意し、テスト0件・skipのみを合格にしない。初回lockfile作成後にnpm ciを検証する。まだ無いコマンドを実行済みとは書かない。

各Taskは、記載した反例をテストにする → 対象機能の不足で失敗することを確認 → 最小実装 → 対象試験・型・build・関連回帰試験 → 自分以外の担当レビュー → 証拠を添えcommit/PR、の順。構文エラーや環境不足を「期待した失敗」と数えない。Task 00の調査、資料と素材は、コード試験の代わりに参照・一覧・表示比較・権利記録を検査する。

証拠はタスクID、要件/AC、対象SHA、端末/ブラウザ、ルール版、seed/操作、コマンドと終了値、実行件数、期待/実際、画像またはログ。例示の点数・HP・抽選重みはテスト専用の値で、採用済みゲーム値ではない。

## PR順序と終了条件

Task番号順ではなく依存順に進める。P0＝00〜02、P1＝03〜07＋11の最小描画（遊べる試作）、P2＝08〜10、P3＝12〜13、P4＝14〜15、P5＝16のモック/承認済み接続、P6＝17の公開前確認、P7＝18と公開後の残確認。11は02の後にGameと並行可。PRはさらに分割できるが、親PRと契約版を明記し、mainへ無断統合しない。

採点・物理・抽選の試作値は公開までに一覧化し、正式採用の記録を残す。数値を決めるための試作は進めてよいが、名称・素材・点数が自動的に利用者承認済みになるわけではない。未指定の別repo、URL、DB識別値を架空の値で埋めない。
