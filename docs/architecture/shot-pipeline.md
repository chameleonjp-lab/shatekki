# 一射の処理設計（Opus → Game担当）

対象：Task 03〜10。型は `src/contracts/` が正本で、この文書はその使い方と処理順を説明する。数値はすべて試作（prototype）で、正式な値ではない。

## 1. 全体の流れ

ゲームの進行（`src/core`）は純粋な関数で書き、時計・保存・描画・通信には触れない。物理（`src/sim`）はRapierの世界を持つが、得点は計算しない。両者の受け渡しは `ShotRequest`（撃つ内容）と `ShotRecord`（一射で起きたこと）だけにする。

1. 画面が `FIRE` を送る。`reduceGame` は撃てる状態（aiming、停止中でない、弾が1以上）のときだけ受け付け、弾を1減らし、発射回数を1増やし、`inFlight`（発射済み・未確定の印）に `ShotRequest` を入れて phase を `resolving` にする。連打しても2回目は phase が違うので無視される。
2. 起点（`src/app.ts`）が印を保存してから `ShotWorld.fire()` を呼ぶ。保存できなかった場合の扱いはTask 10で決める（O11）。
3. `ShotWorld.step(dt)` を毎フレーム呼ぶ。内部は固定刻み（`limits.fixedStepSec`）で進め、描画のフレーム落ちで結果が変わらないようにする。各ステップの `SimulationFrame` を描画へ渡す。
4. 物理側の段階は `flight → transform → settle →（必要なら）grace` の順。
   - flight：コルクが飛ぶ。全コルクが止まる・範囲外へ出る・反射上限に達する、または `maxFlightSec` に達したら終わる。
   - transform：飛行中に景品変更の装置が働いていれば、ここで変身させる（決定32）。対象と変身先は core が渡す `chooseTransform` が決める。耐久値は「残り÷最大」の割合を変身後の最大値に掛け、四捨五入する（試作の丸め方。O08）。台に固定された動く景品は対象にしない（試作）。
   - settle：固定されていない景品の速さが `settleLinearSpeed`・`settleAngularSpeed` 未満の状態が `settleHoldSec` 続けば終わる。周期運動の台は待たない。
   - grace：settle が `maxSettleSec` に達した時点で落下中の景品（下向きの速さが一定以上）があれば、`fallGraceSec` だけ待つ（決定33）。猶予は一射で1回だけで、延長しない。
5. 終わったステップで `ShotRecord` を返す。`resolveShot` が得点台帳・セット・追加弾・終了判定を一度に確定する。続行するときだけ補充し、確定状態を保存する。

一射の最長時間は `maxFlightSec + maxSettleSec + fallGraceSec` を超えない。周期運動の景品が止まるのを待つ処理は入れない。

## 2. コルクの進め方

コルクは剛体にせず、半径 `cork.radius` の球を進行方向へ動かし、Rapierの `castShape` で最初に当たる物を調べる。これで速いコルクが薄い棚をすり抜けない。当たったら次の処理をする。

- 当たった点と面の向き（法線）で `ImpactEvent` を作る。画面外でも必ず作る。
- 反射後の速度は、法線方向の成分に「材質の跳ね返り×弾種の跳ね返り」を掛けて反転し、接線方向は少し弱める。反射の回数を数え、`maxReflectionsPerCork + 弾種の追加分` を超えたら `reflectionLimit` で終える。
- 同じコルクが同じ物に0.05秒以内に再び触れたものは、続いている接触として新しい命中にしない。
- 速さが一定以下になったら `stopped`、`activeBounds` の外に出たら `outOfBounds` で終える。画面に見えないことだけでは消さない。

景品に当たったときは、`damage = baseDamage × 装填の損傷倍率 × 弾種 × 威力倍率 × (今の速さ÷初速)` だけ耐久値を減らし、`impulse = baseImpulse × 装填の押す倍率 × 弾種 × 威力倍率 × (今の速さ÷初速)` の衝撃を当たった点にコルクの進む向きで与える。耐久値が0なら衝撃に `hpZero.pushMultiplier` を掛け、摩擦を `hpZero.frictionMultiplier` 倍にする。耐久値0だけでは獲得にしない（決定06）。

## 3. 仕掛け・店主・隠し対象

仕掛けは壁に付いた板で、コルクは通常どおり反射する。そのうえで、その一射でまだ働いていない装置なら効果を出す（決定31）。元のコルクと分裂したコルクは同じ「使用済み」の記録を共有する。通常の反射は何度でも起きる。

| 装置 | 試作の効果 |
|---|---|
| split | 反射後の向きを法線の周りに ±`splitSpreadRad` 回した2個のコルクに置き換える。世代を1増やす。所持弾は変えない。 |
| power | そのコルクの威力倍率を `powerMultiplier` 倍にする（上限4倍）。 |
| transform | 変身を予約する。実行は飛行の後。 |
| penalty | 減点を1回分記録する。 |
| ammo | 所持弾+`ammoBonus` を要求として記録する。累計の上限は core が適用する。 |
| bulletType | 次の一射の弾種を `bulletTypeCycle` の次に変える（試作：次の一射だけ）。 |

店主の部位と隠し対象は、当たるたびに `firstHitCandidates` に記録する。加点するのは core で、ゲーム内の最初の1回だけにする（決定18）。反応の演出は毎回出してよい。

## 4. 景品と動く景品

景品は種類ごとの形・質量・重心・摩擦で剛体にする。中心が `collectBelowY` より下に来たら獲得とし、その場で物理世界から外して跳ね返りによる再判定を防ぐ。同じ個体は一射でも全体でも1回しか獲得されない。

動く景品（`motion.type` が none 以外）は、台に固定されている間は物理側で台ごと動かす（kinematic）。位相は `clocks.motionSec` から決まり、停止中は進まない。固定中は自分では落ちないので、待つだけで獲得が続くことはない（AC13）。耐久値が0になるか、衝撃が外れる基準を超えたら台から外れ、通常の剛体になる。

## 5. 補充

補充は core の `replenish` が一射の確定後に行う。対象は「その枠に置かれた個体が獲得された枠」と「前から延期されている枠」だけ。枠の `occupancyBox` に未獲得の景品が重なっていれば延期し、景品を消したり動かしたりしない（決定30）。横にずれただけの景品は元の枠の個体のままなので、その枠を補充しない。新しい個体は新しい instanceId で、耐久値は満タンから始まる。

## 6. 抽選（Task 03）

乱数はシード付きの xoshiro128** を使い、状態の4語を `DrawState.rng` に保存する。重みは「難易度の偏りを9個の中で目標数（`tierTargets`）へ近づける係数」と「直近 `historyWindow` 回に出た種類へ `recentPenalty` を掛ける係数」の積とし、0にはしない。セットが必ずそろう保証や、残り1種類を出やすくする補助は入れない（未承認）。
