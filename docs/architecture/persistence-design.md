# 保存・停止・中断の設計（Opus → Game担当、Task 10）

方式は決定24（射撃間の確定状態から再開）と決定27（一射の途中で失われたら中断）に従う。細部（O11）は未確定のため、以下は試作の方式である。正式な扱いは、根拠を添えてChatGPTへ申し送る。

## 1. 保存するもの

保存先はブラウザの端末内保存（localStorage）で、キーごとに役割を分ける。自己ベスト・名前・音・言語・図鑑の発見記録・途中経過を1つのキーにまとめない。

| キー | 中身 | 消してよいか |
|---|---|---|
| `shatekki.run.v1` | 進行中のプレイの `Checkpoint`（版番号 `revision` とタブIDを含む） | プレイが終わり、結果を受け取った後だけ |
| `shatekki.profile.v1` | 自己ベスト（端末内の表示用）、セット図鑑の発見記録 | 消さない |
| `shatekki.settings.v1` | 音のオン・オフ、音量、言語 | 利用者の操作でのみ変える |
| `shatekki.player-name.v1` | ホームの名前欄 | 利用者の操作でのみ変える |
| `shatekki.ranking-pending.v1` | 送信待ちの確定結果（Task 16） | 送信成功を確かめた分だけ |
| `shatekki.quarantine.v1` | 読めなかった・形の合わない保存データの退避先 | 消さない |

## 2. 書き込む時点

一射の流れの中で、書き込みは2回だけにする。

1. `FIRE` が受け付けられた直後、物理を動かす前。弾を1減らした状態と、発射済み・未確定の印（`inFlight`）を書く。
2. 一射の確定後。得点台帳・獲得・セット・追加弾・補充後の棚・抽選の状態を、1つのキーへまとめて書く。印は消える。

補充と抽選の結果は2の書き込みに含まれるので、読み直しても同じ棚になり、二重に抽選しない。装填を止めた直後（`STOP_LOAD` の後）にも書く。これで、装填後に再読み込みしても同じ装填結果のまま狙いから再開でき、装填を引き直せない（AC05）。

## 3. 読み込んだときの扱い

| 保存の状態 | 扱い |
|---|---|
| `inFlight` が残っている | 決定27により中断。完了スコアを送らない。棚を戻して撃ち直させない。図鑑と過去の自己ベストは残す。 |
| phase が position／loading／aiming | 保存した状態から再開する。aimingは同じ装填結果のまま。 |
| phase が ended | 結果画面を出す。送信待ちがあれば同じ内容で再送する。 |
| 形が合わない、版が違う、台帳の不変条件（`isLedgerEntryConsistent`）を満たさない | 退避先へ移し、新しいプレイとして始める。黙って消さない。 |

`rulesVersion` が今の設定と違う保存も退避する（試作の扱い）。古い規則の途中経過を、新しい規則の記録として続けないためである。

## 4. 複数のタブ

保存には `revision`（書くたびに1増える番号）と `tabId` を入れる。書く前に、保存されている `revision` が自分の最後に書いた番号と同じかを確かめる。違えば別のタブが進めているので、このタブでは操作を止め、「別のタブで続いています」と表示する。両方のタブが同じプレイを進めて、弾や点が食い違うことを防ぐ。

## 5. 保存できないとき

保存に失敗しても、ゲームはその場で続けられるようにする。画面には「記録を保存できません。再読み込みすると、このプレイは続きから始められません」と出す。保存できなかった状態を「保存できた」と表示しない。発射前の印を書けなかった場合でも一射は進めるが、そのプレイは送信の対象外にする（試作の扱い。復帰時に中断を判定できないため）。

## 6. 一時停止

一時停止は phase とは別の状態（`pauseReasons`）で持つ。ページが残っている間の停止（別アプリへの切り替え、横向き、手動）と、ページが失われる再読み込みを区別する。停止中は装填のバー・鼓動・物理・動く景品・音を止め、再開しても止まっていた時間をまとめて計算しない。環境の理由（hidden／landscape）が消えても、利用者が「再開する」を押すまで再開しない。
