## 1. 隠しセットがほぼ成立しない

自動プレイで測ると、試作値では1プレイ（10発）で取れる景品は平均3個前後です（上手い人の想定で3.2個、ふつうの人の想定で2.8個）。セットは「同じゲームの中で、決まった3種類をそろえる」方式（決定11・12）です。景品100種類から3〜4種類を集めても、100組のどれかがそろう確率は1プレイあたり0.06〜0.24%しかありません。10種類集めても約7%です。このままでは、隠しセット100種類のほとんどが見つかりません。

Claudeは、未承認の「セットがそろいやすくなる補助」を入れていません（計画1.1とO05）。判断材料として、次の選択肢を示します。数値は `docs/qa/balance-probe.md` の計算に基づく見込みで、実際の手触りは実機で確かめる必要があります。

| 案 | 内容 | 見込み | 決定済み事項との関係 |
|---|---|---|---|
| A | 景品を落としやすくして、1プレイの獲得を6〜10個にする | 成立率 約1〜7%／プレイ | 能力値の調整（O01）だけで済む。難易度とランキングの点の分布が変わる |
| B | 棚の抽選で、同じ分類の景品が並びやすい重みを加える（例：棚の8割が1分類） | 6種類集めたとき約21%、8種類で約44% | 「出現補助」に当たる（O05）。決定03・04（偏りを抑えた抽選・連続抑制）と両立する重み付けにする必要がある |
| C | AとBの組合せ | 20〜40%台 | 上の両方 |
| D | 今のまま。セットはごくまれな発見にする | 0.1〜0.2% | 変更なし。ただし図鑑の100件はほぼ埋まらない |

Claudeとしての推奨は、Cをやや控えめにした案です。具体的には「景品を少し落としやすくする」と「棚の半分〜7割を1分類にそろえる」を組み合わせます。屋台の品ぞろえに統一感が出て、セットのヒントを手がかりに狙う遊びも生まれます。ただし、どの案もランキングで比べる通常モード（決定19）の運の要素を変えます。そのため、正式に採用するかは利用者の判断が必要です。

## 2. 試作値の一覧と、正式化の進め方

すべての数値は `valueStatus: 'prototype'` で、正式ランキングには送らない作りです（`isOfficialRankingEligible`）。主な値の場所は次のとおりです。

| 分類 | 場所 | いまの試作値（要点） |
|---|---|---|
| O01 景品の能力値 | `src/catalog/runtime-config.ts`、`docs/design/tuning-log.md` §1 | 名前から決めた外形・実物に近い質量×0.5・材質の摩擦と反発・耐久値2〜8・基本点10/20/35（難易度別）・動く景品11種 |
| O02 セット | 同上、`src/i18n/hints.ts` | 加点は一律100点、ヒントはClaudeが作った試作の謎かけ（15言語に翻訳済み） |
| O03 技 | `src/catalog/config.ts` | 連鎖は2個目から1個につき+10、反射後の獲得+15、分裂弾での獲得+10 |
| O05 抽選 | `src/catalog/draw.ts`、config | 直近12回に出た種類は重み×0.25、難易度の目標は easy 3・normal 4・hard 2 |
| O07 上限 | config | 反射8回、分裂の世代2、同時コルク8個、飛行4秒、静止待ち5秒、落下猶予1.2秒 |
| O08 仕掛け | `src/core/gimmicks.ts`、`src/sim/world.ts` | 分裂±0.35rad、威力2倍（上限4倍）、減点30点、追加弾+2、弾種変更は次の一射だけ、変身は未獲得かつ固定されていない景品から等確率、変身先は100種から等確率、耐久値は残り割合×新最大値を四捨五入 |
| O09 装填・手ブレ | config | バー周期1.4秒、最良位置0.85、手ブレは1.2秒落ち着いた後に増える |
| O12 店主・隠し対象 | config、`src/contracts/layout.ts` | 帽子30・扇子20・胴10・足元15、隠し対象40（だるま・猫の2つ） |

進め方の提案は2段階です。まず1の判断を受けて、Claudeが能力値と抽選を調整し、測定をやり直します。そのうえで、一覧を「proposed（推奨値）」として利用者へ示します。利用者が採用した値だけを「approved」に変え、決定記録へ追記するPRを出します。

## 3. ランキングの本番接続に必要なこと（参考）

本番のSupabaseを読み取りだけで確認したところ、`public.games` に射的ゲームの登録はありませんでした。新しい受付方式は未登録のゲームの送信を拒否するため、正式ランキングには次の判断と承認が必要です。どれもClaudeは行っていません。

- ゲーム識別値（game_slug）、正式URL（GitHub Pagesの公開を含む）、実験場の詳細ランキングURLを決め、DBへ登録すること
- 名前なしのプレイの開始回数を数えるか。参照したゲームは匿名の開始も数えていますが、本作は送っていません
- 本人の順位を確実に出すため、本人の順位を返すサーバー側の仕組み（RPC）を追加するか。現在は、上位30名の中で同じ名前と点の行が1つだけのときに限って表示しています
