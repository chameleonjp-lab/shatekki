- 文書版：1.0 / 作成日：2026年11月6日
- 対象リポジトリ：`chameleonjp-lab/shatekki`
- 公開タイトル：未確定。本資料では「屋台の射的ゲーム」と呼ぶ。
- 状態：基本方式は承認済み。個別数値・素材・一部の境界条件は未確定。
- 対象作業：要件資料の作成。ゲーム実装、データベース変更、本番公開は含めない。

## 1. 目的と資料の読み方

屋台の景品を狙い、当てる位置や装填の上手さで落とし方を工夫する。コルクの反射、分裂、景品同士の連鎖、100種類の隠しセットにより、狙った成功と意外な成功の両方を楽しめるゲームにする。

「確定」はユーザーが指定または採用した方式。「候補」は既存案を引き継いだ名称・素材・追加要素。「未確定」は数値や処理順など、まだ決定していない内容。実装の安全条件は二重加点や復帰時の不整合を避ける条件であり、新しいゲームモードを追加する決定ではない。

原資料は『屋台の射的ゲーム_要件アイデアリスト_v3.docx』と本会話。旧版の検討案より、[決定記録](decision-log.md)の26項目と本書の確定事項を優先する。共通画面仕様は依頼済みの共通要件を記載したもので、他ゲームの実装が全て同一であると確認した報告ではない。

## 2. 確定した基本仕様

| 項目 | 要件 |
|---|---|
| 端末・向き | iPhoneの縦向きを主にする。横向き専用のゲーム画面は作らない。 |
| 表現 | 動作負荷を抑えた3D。自由に歩き回る方式ではない。描画・衝突計算に使うライブラリは未選定。 |
| 景品 | 100種類を用意する。同時に置く景品は9個、基本は3段×3個。 |
| 隠しセット | 100種類。各セットは異なる景品3種類を各1個集めると成立する。 |
| 弾 | 初期10発。追加できる所持弾は1ゲームで累計10発まで。発射機会は最大20回。 |
| 補充 | 一射の反射・落下・連鎖が終わった後、空き場所へ新しい景品を補充する。 |
| 終了 | 最後の一射の処理後、追加分を含めて撃てる弾が0なら終了する。全取りでは終了しない。 |
| 得点 | 景品獲得点＋技の加点＋セット加点−減点。合計の下限は0点。 |
| ランキング | 難易度の偏りを調整したランダム配置の通常モードを比較する。運の差は残る。 |
| 共通画面 | ホームと結果の操作・名前入力・ランキング・X共有・言語・音設定を共通要件へ合わせる。 |

9個・最大20回は採用した初期設定。実機調整の結果を記録せず、別の方式や大幅に異なる値へ変えない。

## 3. 一射の流れ

`位置を選ぶ → 弾を込める → 狙う → 撃つ → 反射・落下・連鎖を処理 → 得点と残弾を確定 → 続行なら補充 → 次の位置選び`

立ち位置は屋台の正面を左右に移動して選ぶ。立ち位置の移動と、立った場所から見る方向を変える操作を分ける。前回の位置を引き継いで続けられる構成を基本にする。

装填は動くバーをタイミングよく止める。結果は耐久値を減らす量と景品を押す力の両方へ影響する。装填の具体的な段階数、倍率、バー速度は未確定。発射操作を受け付けた時だけ所持弾を1発消費する。

照準にはゲーム内の鼓動による揺れを付け、狙い続ける時間によって揺れ方を変える。実際の心拍数や端末センサーとの連動は使用しない。揺れの式・増加量・落ち着く間隔は調整対象であり、照準に見えない追加のずれを入れる前提にはしない。

一射から分かれた弾、景品同士の接触、その結果の落下をまとめて一射として扱う。次の弾は、この処理が終わるまで撃てない。弾や景品が落ち着くまで処理するが、時間・反射・分裂などの上限を設ける。元から周期運動する台や背景の飾りが止まるのを待つ仕組みにはしない。

## 4. 景品・獲得・補充

景品ごとに耐久値、落ちにくさ、命中箇所による後方へのずれ方を変える。形、重さ、重心、滑りやすさなどの組み合わせで違いを作るが、各景品の具体的な値は未確定。

耐久値が0になったら倒れやすくする。0になっただけで即獲得・破壊とはしない。耐久値が残っていても所定の回収位置まで落とせれば獲得する。棚の上で倒れた状態、端に引っかかった状態、下の棚に乗った状態は、それだけでは獲得にしない。

一度獲得した個体は、跳ね戻りや複数接触で再加点しない。景品の種類を表す番号と、棚上の個体を表す番号を分ける。新しく補充した個体へ前の個体の傷みや獲得済み状態を流用しない。

抽選は種類と難易度の偏りを抑える。同じ景品が連続して出る可能性を下げるが、完全禁止にはしない。抽選の重みや連続とみなす範囲は未確定。特定セットの必ず成立する配置保証や、残り1種類の出現率を上げる補助は、まだ確定していない。

動く景品は一定周期で動かす。往復・回転・振り子は候補。待っているだけで自動落下して得点し続ける配置にしない。補充の配置と既存景品がぶつかる場合、特に別の棚へ移った景品がある場合の扱いは未確定事項に残す。既存の景品を消して9個へ戻す方法は使わない。

## 5. 反射・背景の仕掛け・店主

コルクは当たる場所と角度に応じて反射する。画面外でも屋台の有効範囲内なら判定を続ける。見えなくなったという理由だけで消去・加点しない。反射で隠れた対象に当たった成功には方向と短い説明を出す。

| 仕掛け | 必要な効果 | 未確定の詳細 |
|---|---|---|
| 分裂板 | 飛行中のコルクが2個になる。所持弾は増やさない。 | 分かれる角度、威力の配分、同時個数、再分裂上限。 |
| 威力倍の板 | 接触後の弾の威力を2倍にする。 | 重複範囲、全体倍率上限、弾速も変えるか。 |
| 景品変更 | 背景の仕掛けで対象景品の種類を変える。 | 対象選び、発動時点、耐久値・位置・得点・セット判定の引継ぎ。 |
| 減点札 | 命中で減点し、何に当たったかを示す。 | 点数、再発動条件、下限0の適用順序。 |
| 所持弾＋2 | 次に撃てる弾を2発増やす。追加累計は最大10発。 | 札ごとの使用回数、配置、補充との関係。 |
| 弾種類変更 | 重い弾や跳ねやすい弾などへ変える。 | 種類の確定、持続範囲、複数板の優先順。 |

同じ仕掛けは分裂弾を含めて一射1回まで、景品変身は弾の運動後に行い位置と残り耐久値の割合を引き継ぐ、という旧資料の案は有力な補足案として残す。ただし、26項目の承認だけで全ての仕掛けの詳細が確定したとは扱わない。

屋台の端に店主を置き、当たった部位ごとに演出と得点を変える。帽子・扇子・胴・足元は部位候補。店主と隠し対象への加点は、同一対象・同一部位について1ゲームの最初の命中だけ。反応演出は繰り返し出す。具体的な部位・点数・隠し対象は未確定。

景品同士の押し合いによる連鎖、店主の持ち物での反射、動く反射板、幕や風鈴は既存の候補として扱う。元案にある反射・店主・画面外の加点を、候補扱いによって削除しない。

## 6. 隠しセット100種類

同じゲーム内の累計獲得から、異なる3種類を各1個そろえる。順番は問わない。同じ獲得景品を複数セットの条件に使用でき、セット成立で景品を消費しない。

同一セットの加点は1ゲームにつき1回。別のゲームでは取り直せば再度加点する。過去のゲームで取った景品を、今回の成立条件へ混ぜない。

発見済みのセットは図鑑に残す。未発見のセット名は伏せ、発見につながるヒントを示す。図鑑の発見記録と、現在のゲームの獲得状況を別に管理する。保存方法やヒント文は未確定。

複数セットが同時に成立する場合は、成立した各セットを一度ずつ集計する。まとめ取り・反射などの技ボーナスは、100種類のセット数に含めない。名称と組み合わせは[セット候補100件](set-candidates.md)へ原資料から引き継ぎ、点数は未設定のままにする。

## 7. 採点と結果の確定

景品獲得・技・セット・減点を分けて記録する。店主や隠し対象の初回加点は、内訳に含まれることが分かる形にする。各景品の基本点、セット点、技点、減点、最大連鎖の定義は未確定。

合計得点の下限は0。ただし「各出来事のたびに0へ戻す」「一射を合計した後で0へ戻す」「最終合計だけ0へ戻す」は結果が異なるため、まだ勝手に選ばない。得点内訳と表示合計が一致する方式を決める。

数字が飛ぶ演出やカウントアップとは別に、加点済みの記録を持つ。演出省略、一時停止、再試行によって点数を増減させない。最終確定値を、結果画面・自己ベスト・ランキング送信・X共有の全てで共用する。

## 8. ホーム画面と共通機能

ホームにはタイトル、はじめる、あそびかた、任意の名前入力、自己ベスト、ランキング、Xでシェア、言語設定、音設定を置く。主な開始操作が長い説明の下に埋もれない構成を目指す。

名前欄の説明は「名前を入力すると、名前と記録がランキングに公開されます。空欄でも遊べます。」。空欄でもゲームを遊べる。開始時に有効な名前があったプレイだけ自動登録を試み、終了後の追加入力で過去の匿名プレイを公開しない。名前の変更・消去は以後のプレイへ適用する。

名前が同じだけで参加者を統合しない。文字を画面に安全に表示し、名前をプログラムとして実行しない。名前の文字数や入力制限は既存の共通仕様を確認して合わせ、独自の管理画面や審査機能は追加しない。

「ランキング」は実験場におけるこのゲームの詳細ページへ移動する。詳細ページと正式公開URLは未確定であり、推測のURLや他ゲームのページを埋め込まない。

「Xでシェア」は黒背景・白文字。ホームでは紹介文と正式URL、結果では今回の確定結果・必要な単位・モードと正式URLを共有する。投稿画面を開く機能であり、自動投稿しない。開けない場合のコピー手段も用意する。

## 9. 射的固有の結果画面

総得点を中心に、獲得景品、成立セット、最大連鎖、得点内訳を射的らしく見せる。景品を並べる見せ方や代表景品の強調は候補であり、デザイン・評価名・称号は未確定。前の説明に出た仮スコアや仮の景品を仕様値として使わない。

共通部分は自己ベスト、更新表示、登録完了後の自己ベスト基準の順位、上位30名、もう一回、ホーム、ランキング、Xでシェア。今回の点が自己ベストを下回っても、それを理由に自己ベスト順位を下げない。名前なしのプレイでは本人順位を表示しない。

縦画面の最初の範囲で結果と再挑戦の操作が分かるようにし、景品・内訳・上位30名は必要に応じて下へスクロールして読む。全てを小さく縮めて一画面へ押し込まない。

## 10. ランキングと通信

集計は参加者ごとの自己ベスト、同点は同順位（1位が2人なら次は3位）。表示対象モード、期間、除外条件を実験場の詳細ページと一致させる。上位30名は参加者でまとめた後の最大30人であり、単なる直近30回のプレイではない。

登録中、成功、送信待ち、失敗を区別し、本人順位は登録成功後に最新集計で表示する。上位一覧には読み込み中・記録なし・失敗・再試行を用意する。送信失敗でローカルの確定結果を失わず、再送で同じプレイを二重登録しない。

難易度を調整した抽選でも運による差は残る。全員同じ配置の競技、練習、追加モードは本決定に含めない。異なるルール版の記録を混在させる場合の扱いは公開前に決める。

保存先、ゲーム識別値、参加者の識別方法、開始・終了送信の具体的な項目は既存連携を調べて決める。今ある記録や他ゲームのデータは削除・初期化しない。秘密鍵をクライアントやこの公開リポジトリに入れない。本資料作成では外部サービスへの接続・変更は行わない。

## 11. 言語・音・演出

対応言語は共通の15言語：日本語（ja）、英語（en）、スペイン語（es）、ブラジルポルトガル語（pt-BR）、簡体字中国語（zh-Hans）、フランス語（fr）、ドイツ語（de）、韓国語（ko）、ロシア語（ru）、イタリア語（it）、繁体字中国語（zh-Hant）、インドネシア語（id）、トルコ語（tr）、ベトナム語（vi）、タイ語（th）。

ホーム、あそびかた、ゲーム中、景品名、セット名とヒント、結果、ランキング、設定、名前説明、通信状態、X共有文を対象にする。保存した言語を優先し、未設定ならブラウザ言語、該当しなければ英語。表示言語が変わっても採点・景品・セットの識別値は変えない。進行中の言語変更でゲームを壊さない扱いを決める。

音は初回オンで音量を0より大きくする。保存済みのオフ・音量0は尊重し、音量と消音を変更できるようにする。選択、確定、キャンセル、開始、装填、発射、材質別の命中、反射、分裂、仕掛け、獲得、セット、終了、結果、自己ベスト更新などに必要な効果音を洗い出す。具体的な音源は未選定。

画面内の全ての命中位置には小さな反応を付ける。大きな演出は獲得や珍しい成功に寄せ、同じ接触が続く状態で音や加点を連打しない。「惜しい」はかすめた・端に残ったなどの実際の結果に合わせ、「ハズレ」は後から成功する反射を処理してから判断する。

長い演出は省略できるが、衝突・落下・得点計算は省略しない。無音でも効果や得点の理由を理解できる表示を残す。派手さを抑える設定は追加候補であり、軽量化でルールを変えない。

## 12. 一時停止・保存・復帰

画面外への切替や横向きへの変更では操作・装填・弾・景品・音の進行を止める。縦向きへ戻す案内を出し、再開時に誤射、時間の飛躍、二重加点が起きないことを確認する。

一射が終わった確定状態を保存し、そこから再開する方式を採用する。弾の飛行中の完全復元は対象外。ただし、発射後にページが読み直された時の「消費した弾・未確定の結果」の扱いは未確定。単に前の保存点へ戻して、都合の悪い一射を無制限に撃ち直せる実装にしない。

保存対象には残弾、累計追加弾、確定得点と内訳、棚の状態、取得済み景品、成立済みセット、店主・隠し対象の初回加点済み状態などが必要になる。具体的な保存項目、装填後から発射前の復帰、抽選の続き、保存に失敗した時の扱いは詳細設計で定める。途中復帰と新規プレイを混同しない。

## 13. 今回含めないこと

ゲーム実装、画面の完成デザイン、100景品の3D素材制作、全言語翻訳の完成、本番ランキング接続、データベース変更、Pagesなどの公開設定、PRのマージは今回の資料作成に含めない。実測心拍、横向き専用画面、自由歩行、時間切れ方式、同条件の競技モード、息止め操作、お題は追加承認なしに導入しない。

ゲーム公開後にマージ内容を自動反映する共通運用は、後続の公開工程で扱う。今回の格納を、ゲームの本番公開や実験場への新規掲載の承認とは扱わない。

## 14. 未確定項目と確認方法

詳細は[未確定事項](open-items.md)と[受入確認項目](acceptance-criteria.md)を参照する。未確定値を仮に置く場合は「試作用」と明記し、ルールの選択や本番確定をしたことにしない。

この資料の作成時点ではゲームの動作確認は未実施。候補100件の件数、参照先、重複を点検したことと、ゲーム実装のテスト合格は別に扱う。
