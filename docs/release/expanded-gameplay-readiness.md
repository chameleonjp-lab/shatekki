# 追加機能（D34〜D37）を正式に切り替える前に必要なこと

2026年11月6日。この文書は、追加機能をいまの内部試作から正式な遊び方へ切り替えるときの判断材料をまとめたものです。この文書を書いたことや、この文書を含むPRをマージしたことで、切り替えが決まるわけではありません。切り替えるかどうか、いつ切り替えるかは利用者が決めます。

## いまの状態

公開しているゲームは、これまでどおり `official-v1`（rules-v1）で動いています。追加機能は、内部試験用のビルド設定（`VITE_SHATEKKI_BUNDLE=expanded-proposed`）を付けてビルドしたときだけ動きます。URLのパラメータやメニューからは開けません。内部試験用ビルドは、公開用の配信（Pages）が使う `site-dist` とは別の名前で保存しています。そのため、いまの設定のままでは公開されません。

追加機能のルール版は `rules-v2-proposed-r001`、値の状態は prototype（試作）です。この版の記録は、旧ルールとは別の保存場所に書きます。ランキングには送りません。旧ルールの保存、自己ベスト、図鑑、名前、設定、送信待ちのデータには手を触れません。

## 切り替えの前に決めてほしいこと

ここに挙げることは、どれもまだ決まっていません。試作の値で動いているだけです。

| 項目 | 決めること | いまの試作 |
|---|---|---|
| C01 | 300組の構成・名前・ヒント・点数 | 付録どおりの300組、1組50点。ヒントは機械で書いた文案 |
| C02 | 200問と400の選択肢の文面・抽選先 | 付録どおり |
| C03 | 20シリーズ・100効果の値と細かいきまり | 付録の提案値。分裂角の倍率の範囲は0.75〜1.5倍にした |

| C05 | 保存の版分け・中断・旧記録の扱い・15言語 | 別のキーへ保存。15言語は機械翻訳で、母語話者の確認はまだ |

ほかに、実装の途中で出た解釈の判断が4つあります（`docs/handoff/to-chatgpt/2026-11-06-1700-claude-expanded-judgement-calls.md`）。いちばん影響が大きいのは、背の高い種類への変化が延期されやすい件です。自動の打ち手で測ったところ、種類を変える予定の約16%が延期になりました。

## 切り替えの前に確かめてほしいこと

自動の試験では確かめられないことが残っています。

- iPhone Safari実機で、毎秒のコマ数、両端・上下段・店主への狙いやすさ、質問パネルの読みやすさ、効果の結果の表示、音を確かめること
- 人が遊んだときの景品の取れ方とセットの成立のしかた（自動の打ち手の数字だけで点数を決めない）
- 15言語の文章を、それぞれの言語を母語とする人が読むこと
- 確認条件44項目の結果（`docs/qa/expanded-gameplay-evidence.md`）で、未確認として残った項目

## 切り替えのしかた（案）

切り替えると決まったら、別のPRで次のことを行います。この文書の作成では、まだ何も変えていません。

1. 採用した値で新しい正式版のスナップショットを作り、新しいルール版の名前を付けます。`data/release-approved-v1.json` は上書きしません。試作版（`rules-v2-proposed-r001`）の記録を、正式版の記録へ昇格させることもしません。
2. 公開用ビルドの既定を新しい正式版へ変えます。このPRで、公開用ビルドに新しいデータが入ることと、旧ルールの記録が残ることを確かめます。
3. ランキングに新しい版を載せるかどうかは、データベースの変更を含むので、別に整理して利用者の承認を得ます。今回の実装はデータベースを前提にしていません。

## 戻し方

旧ルールへ戻すときは、公開用ビルドの既定を `official-v1` に戻すPRを作ります。新しい版の保存や図鑑は消しません。Gitの履歴を書き換えることや、データを消すことは、戻し方に使いません。
