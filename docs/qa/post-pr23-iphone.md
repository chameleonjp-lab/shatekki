# iPhone 17 Pro Safari 実機記録

対象候補は `expanded-next`（rules-v2-proposed-r006）。実機での観察者・日時・OS/Safari・コミット・画面寸法・結果は未記入。確認ページは利用者が配信を判断する。

## 確認ページの準備・配信・撤収

1. 候補を含む最新mainのSHAとciの成功を確認する。Actionsの `next-preview` をmainから手動実行し、`source_sha` にそのSHA、`operation` に `prepare` を指定する。1日保管の試験用成果物を作る。
2. 公開期間とActions・Pages利用枠を利用者が確認する。配信するとURLを知る人がアクセスできる。課金設定の変更は不要。利用者が公開を決めた場合だけ、同じSHAで `publish` を選ぶ。ルートは同じmainの9枠版、確認先は `/shatekki/preview/rules-v2-proposed-r006/`。候補ページの `version.json` にコミットとビルド指定を収録する。
3. 確認が終わったら、最新mainのSHAで `withdraw` を選ぶ。9枠の正式URLを直接開いて再読込し、以前の記録を確認する。次回の通常配信も正式版だけを配信する。各配信は `pages-main` で直列化し、直前にmainとCIの実行回を照合する。

## 実機で記録する操作

Safariの独立したテスト用プロファイルで同じタブを使う。画像・計測ログとともに、各行に観察日時、iOS/Safariの版、候補コミット、画面幅×高さ、実際の結果を記録する。

|操作|期待する結果|観察|
|---|---|---|
|9枠の正式URLで回を開始。候補下の `record-check.html` で旧記録を控え、候補で開始・一射・終了後、同じタブの照合ボタンを押す。正式URLを再読込|旧キーは全行「一致」。正式版は元の9枠の回に戻れる。r003キーが使用済みなら投入を拒む|未測定|
|縦で両端・上下段と5装置を狙う。横に回して縦に戻し、アプリを切り替えて復帰する|立ち位置・照準・結果が一致。停止中に射や音が進まず、操作を再開できる|未測定|
|Safariのツールバーを表示して質問の最後の選択肢をタップし、別の回で質問中・保存中に再読込する|短い表示でも押せる。確定済みの射が二重加算されず、中断済みの射をやり直せない|未測定|

r006 の同時コルク数の設定上限は8。通常の発射は最大3個で、分裂板は1枚、1射に1回だけ親1個を子2個に置き換える。通常ルールで到達できる最大は4個。r006 の Rapier 試験で3発を分裂板へ当て、同時4個、分裂1回と射の終了を確認した。計測画面は実際のコルク数別に集計する。8個の実機負荷は未測定として残し、4個の結果をその欄に転記しない。[対象試験](../../tests/integration/expanded-performance.test.ts)

公開後の実URLと実機の結果、撤収後の旧記録は未確認。

ローカルの配信用成果物は `265c7e7`（r006）で Chromium から確認した。9枠の正式入口と候補の直リンク・再読込、候補での一射、計測結果の版とコミット、旧キーの全行一致、同じサイトでのr003と9枠の再開が成功した。確認したURLはローカルサーバー内。iPhoneの観察欄は利用者の測定後に更新する。
